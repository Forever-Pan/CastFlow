Abstract

Bridging evidence acquisition and prediction.

Time series forecasting is a fundamental task in temporal data analytics, and large language model (LLM)-based agents offer a promising paradigm through autonomous tool interaction and evidence-grounded reasoning. However, two fundamental challenges remain: how to acquire forecast-relevant evidence through adaptive tool interactions, and how to translate such evidence into accurate numerical predictions. To address these challenges, we propose CastFlow, a role-specialized agentic forecasting framework that bridges general-purpose tool reasoning and specialized temporal forecasting. Specifically, CastFlow introduces an Experience Memory that distills successful tool-use trajectories from training data, guiding a frozen LLM to orchestrate a multi-view toolkit for evidence acquisition. A lightweight specialized LLM then performs evidence-grounded temporal reasoning to refine an ensemble forecasting prior. To enhance this capability, we develop a two-stage training strategy combining supervised fine-tuning and reinforcement learning with verifiable rewards, where final forecasting outcomes of the overall workflow guide the optimization of the specialized model. Extensive experiments on ten real-world benchmarks demonstrate that CastFlow outperforms competitive baselines on nine datasets. Our findings highlight the importance of bridging autonomous evidence acquisition and specialized temporal reasoning for accurate and adaptive agentic forecasting. The source code is available at https://github.com/Forever-Pan/CastFlow.

Motivation

Why a workflow instead of one generation?

Time series forecasting needs more than fluent explanation. A useful model must identify local patterns, compare similar historical cases, reason about covariates and events, and decide when a baseline should be preserved, shifted, or corrected.

CastFlow therefore exposes the forecasting process as a chain of inspectable states. The workflow keeps reasoning, evidence acquisition, numerical revision, and validation separate, so their roles and intermediate outputs can be inspected and evaluated. Only the forecasting model is updated during SFT and RLVR.

This is the central reason for introducing an agentic workflow: the goal is not to make the model produce longer rationales, but to make forecasting decisions depend on explicit evidence and verifiable intermediate artifacts.

Method

A four-role workflow with explicit intermediate artifacts.

CastFlow assigns each part of the forecasting process to the model or module best suited for it, rather than forcing a single LLM call to plan, analyze, forecast, and self-correct at once.

  1. 01

    Planning

    Retrieves successful historical trajectories from strategy memory and decides which tools are needed for the current lookback window.

  2. 02

    Action

    Executes tools to extract temporal statistics, trend signals, covariate effects, and an ensemble forecast baseline. The residual diagnoser is used only during training.

  3. 03

    Forecasting

    Uses the fine-tuned local LLM to revise the ensemble baseline according to retrieved experience, domain context, and tool evidence.

  4. 04

    Reflection

    Checks horizon length, output format, and evidence alignment, then triggers bounded correction when the response violates the task contract.

Role specialization

The frozen LLM is preserved for semantic reasoning, tool scheduling, and verification. The trainable local model is reserved for the quantitative subproblem where supervised and reinforcement signals are available: correcting a forecast baseline.

Memory-guided planning

Successful trajectories are stored as procedural experience. At inference time, similar historical cases help the planner reuse effective tool sequences and avoid starting from scratch on every window.

Multi-view toolkit

The toolkit covers ensemble anchoring, statistical and spectral profiling, dynamic pattern monitoring, and training-side residual diagnosis. Test-time tools use information available at the forecast origin, including previously issued auxiliary forecasts where applicable.

Training

Workflow context trains evidence-guided forecasting.

CastFlow collects tool-use experience from training windows. SFT trains the local forecasting model on selected teacher responses conditioned on workflow context. RLVR scores candidate forecasting responses directly; the planner and reflection model remain frozen.

Trajectory collection K-parallel exploration records plans, tool calls, evidence, and successful corrections.
SFT warmup The local model learns the response protocol and how to condition forecasts on evidence.
GRPO-based RLVR Candidate forecasts are optimized with verifiable rewards instead of a learned value model.
Hybrid MSE reward Absolute accuracy and improvement over the ensemble baseline are balanced to reward useful correction.

Experiments

Forecasting results across ten benchmarks.

CastFlow is evaluated on electricity markets, power-grid temperature, renewable energy generation, and streamflow. It is compared with statistical models, tree models, deep forecasters, foundation models, LLM forecasters, and agentic forecasting baselines.

Short horizon 5 electricity-market datasets

BE, DE, NP, FR, and PJM use a 168-hour lookback window and a 24-hour forecast horizon.

Long horizon 5 cross-domain datasets

ETTh, ETTm, WP, SP, and MOPEX use 96-step horizons across grid, renewable, and streamflow domains.

Comparison scope 21 baselines

The benchmark covers statistical, tree-based, deep, foundation, LLM-based, and agentic forecasting methods.

Analysis

Where do the gains come from?

The ablations compare complete forecasting configurations. The trajectory plots and case study illustrate selected windows and the intended information flow.

Representative ablation evidence
Study Removed or varied What it shows Representative numbers
Core workflow w/o Reflection Removing reflection disables self-correction in the evaluated configuration; this comparison does not isolate semantic reflection from structural checks. BE MSE 1027.76 vs 546.87; WP 5102.29 vs 1719.99.
Core workflow w/o Toolkit The configuration removes the ensemble prior and diagnostics together with their dependent tool planning. ETTm MSE 17.68 vs 2.36; WP 3517.03 vs 1719.99.
Toolkit w/o Anchorer Removing the anchorer yields the largest MSE increase among toolkit-category removals on every reported dataset. PJM MSE 47.89 vs 27.45; WP 2718.42 vs 1719.99.
Reward Hybrid MSE The combined reward gives the lowest MSE on the four evaluated datasets; DE has a small MAE exception. Best MSE on BE, DE, SP, and ETTh among reward variants.

Workflow execution

Reuse diagnostics. Resume committed forecasts.

Separate execution studies examine repeated diagnostic computation and recovery after a controlled interruption.

Diagnostic feature reuse

2.24–2.98× under full-tool plans

Current-plan reuse preserves identical diagnostic outputs across six datasets. Speedups are 1.11–1.45× under fresh planning; measurements cover diagnostic computation.

Controlled interruption recovery

1.98× median paired speedup

For 35 pairs reaching the post-forecast interruption point, resuming committed stages preserves final predictions and reduces forecast calls from 70 to 35. Normal execution times remain similar.

The recovery study uses fixed full-tool plans, deterministic validation, and dataset-specific SFT-plus-RLVR checkpoints. These execution measurements use a separate experiment implementation; see the paper and runtime notes for their scope.

Code

Repository structure follows the paper workflow.

The public implementation provides entries for case-library construction, experience memory, forecasting-model training, inference, and evaluation. Data, checkpoints, and generated libraries are supplied separately. Public defaults are documented in the repository.

01

Anchorer Library

Build the Foundational Anchorer case library so tool use can start from similar historical examples and ensemble priors.

02

Strategy Memory

Construct cross-domain strategy memory from successful planning and tool-use trajectories.

03

SFT and RLVR Data

Export context-response pairs for SFT and forecasting contexts with numerical targets for response-level RLVR.

04

Forecast and Evaluate

Serve the trained model, forecast test windows, and evaluate predictions with the same metrics used in the paper.
