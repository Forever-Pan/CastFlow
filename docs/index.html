Abstract

Forecasting as evidence-guided correction.

LLM-based forecasting is often formulated as direct sequence generation: the model receives a historical window and produces future values in a single pass. This formulation makes it difficult to acquire contextual evidence across multiple rounds, inspect intermediate reasoning, combine reliable ensemble priors, or repair invalid forecasts after generation.

CastFlow reframes the task as a role-specialized agentic workflow. Planning selects the evidence needed for the current window; Action invokes deterministic diagnostic tools; Forecasting uses a fine-tuned Qwen3-4B local model to revise an ensemble baseline; Reflection verifies format, horizon length, and evidence consistency before returning the final forecast.

The key separation is functional rather than cosmetic: a frozen general LLM handles broad reasoning and verification, while the trainable local model focuses on the narrower numerical task of baseline correction. Workflow-oriented SFT and GRPO-based RLVR further teach the forecaster to use retrieved experience, tool evidence, and measurable reward signals.

Motivation

Why a workflow instead of one generation?

Time series forecasting needs more than fluent explanation. A useful model must identify local patterns, compare similar historical cases, reason about covariates and events, and decide when a baseline should be preserved, shifted, or corrected.

CastFlow therefore exposes the forecasting process as a chain of inspectable states. The workflow keeps reasoning, evidence acquisition, numerical revision, and validation separate, so each component can be trained, ablated, and audited.

This is the central reason for introducing an agentic workflow: the goal is not to make the model produce longer rationales, but to make forecasting decisions depend on explicit evidence and verifiable intermediate artifacts.

Method

A four-role workflow with explicit intermediate artifacts.

CastFlow assigns each part of the forecasting process to the model or module best suited for it, rather than forcing a single LLM call to plan, analyze, forecast, and self-correct at once.

  1. 01

    Planning

    Retrieves successful historical trajectories from strategy memory and decides which tools are needed for the current lookback window.

  2. 02

    Action

    Executes deterministic tools to extract temporal statistics, trend signals, covariate effects, residual patterns, and an ensemble forecast baseline.

  3. 03

    Forecasting

    Uses the fine-tuned local LLM to revise the ensemble baseline according to retrieved experience, domain context, and tool evidence.

  4. 04

    Reflection

    Checks horizon length, output format, and evidence alignment, then triggers bounded correction when the response violates the task contract.

Role specialization

The frozen LLM is preserved for semantic reasoning, tool scheduling, and verification. The trainable local model is reserved for the quantitative subproblem where supervised and reinforcement signals are available: correcting a forecast baseline.

Memory-guided planning

Successful trajectories are stored as procedural experience. At inference time, similar historical cases help the planner reuse effective tool sequences and avoid starting from scratch on every window.

Multi-view toolkit

The toolkit covers ensemble anchoring, statistical and spectral profiling, dynamic pattern monitoring, and residual diagnosis. These tools provide evidence without leaking unavailable future values.

Training

Workflow-level data turns tool use into trainable behavior.

CastFlow first collects successful tool-use trajectories through K-parallel exploration, then uses them to train the local forecasting model with SFT and GRPO-based RLVR.

Trajectory collection K-parallel exploration records plans, tool calls, evidence, and successful corrections.
SFT warmup The local model learns the response protocol and how to condition forecasts on evidence.
GRPO-based RLVR Candidate forecasts are optimized with verifiable rewards instead of a learned value model.
Hybrid MSE reward Absolute accuracy and improvement over the ensemble baseline are balanced to reward useful correction.

Experiments

Consistent gains across heterogeneous forecasting domains.

CastFlow is evaluated on electricity markets, power-grid temperature, renewable energy generation, and streamflow. It is compared with statistical models, tree models, deep forecasters, foundation models, LLM forecasters, and agentic forecasting baselines.

Short horizon 5 electricity-market datasets

BE, DE, NP, FR, and PJM use a 168-hour lookback window and a 24-hour forecast horizon.

Long horizon 5 cross-domain datasets

ETTh, ETTm, WP, SP, and MOPEX use 96-step horizons across grid, renewable, and streamflow domains.

Comparison scope 21 baselines

The benchmark covers statistical, tree-based, deep, foundation, LLM-based, and agentic forecasting methods.

Main result Best MSE and MAE on 9 of 10 datasets, including all 5 long-horizon benchmarks.

PJM is the only exception on both metrics: Chronos gives the lowest MSE, while AlphaCast gives the lowest MAE. The homepage keeps this exception visible because the experimental claim should remain specific rather than over-aggregated.

Analysis

Where do the gains come from?

The ablations test whether the workflow components are necessary, while the trajectory and case figures show how CastFlow changes the numerical forecast rather than only producing explanations.

Representative ablation evidence
Study Removed or varied What it shows Representative numbers
Core workflow w/o Reflection Invalid length, response format, and evidence-alignment errors are no longer corrected. BE MSE 1027.76 vs 546.87; WP 5102.29 vs 1719.99.
Core workflow w/o Toolkit The forecaster loses structured diagnostic evidence and relies mostly on parametric knowledge. ETTm MSE 17.68 vs 2.36; WP 3517.03 vs 1719.99.
Toolkit w/o Anchorer The ensemble prior is the strongest single toolkit dependency. PJM MSE 47.89 vs 27.45; WP 2718.42 vs 1719.99.
Reward Hybrid MSE Absolute accuracy and improvement over the baseline must be optimized together. Best MSE on BE, DE, SP, and ETTh among reward variants.

Code

Repository structure follows the paper workflow.

The public repository exposes the same sequence used in the paper: build reusable forecasting priors, distill workflow memory, train the local forecaster, then run and evaluate test-time forecasts.

01

Anchorer Library

Build the Foundational Anchorer case library so tool use can start from similar historical examples and ensemble priors.

02

Strategy Memory

Construct cross-domain strategy memory from successful planning and tool-use trajectories.

03

SFT and RLVR Data

Export workflow-oriented supervised data and reinforcement trajectories for the local forecasting model.

04

Forecast and Evaluate

Serve the trained model, forecast test windows, and evaluate predictions with the same metrics used in the paper.
